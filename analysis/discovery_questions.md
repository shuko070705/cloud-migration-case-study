対象企業：Nexus Solutions Inc.（架空企業）

## Q01 — 現在のサーバーの用途

### 質問

現在のサーバーの主な使い方についてお聞きしてもよろしいですか。

### 質問の目的

現行インフラの用途とビジネス上の重要性を把握する。

### クライアントの回答

法人向け業務管理ソフトウェアの提供を主な目的としている。

| サーバー | 用途 |
|---|---|
| Web Server | HTTPリクエストの受付 |
| Application Server | 業務処理・認証・API |
| Database Server | 顧客情報・業務データの保存 |
| File / Backup Server | ファイル保存・バックアップ |

その他の情報：

- 開発・テスト環境も運用している
- 24時間365日サービスを提供している
- 平日9時〜18時にアクセスが集中する
- ピーク時間帯に処理速度が低下することがある

### 分析・気づき

- 時間帯によって処理負荷が異なる。
- サービスの可用性が重要である。
- 負荷に応じたリソース調整が有効である可能性がある。

### 追加確認事項

- 現在のサーバー台数とスペック
- ピーク時のCPU・メモリ使用率
- 許容可能なサービス停止時間

### 分析・気づき

## Q03 — データベースの負荷が高い原因

### 質問

なぜデータベースの負荷が高くなっているのでしょうか。

### 質問の目的

- 性能低下の根本原因を調査する
- 現在のインフラと処理負荷の関係を把握する
- 改善策を検討するための情報を収集する

### クライアントの回答

#### 1. 顧客数・データ量の増加

| 項目 | 5年前 | 現在 |
|---|---|---|
| 法人顧客数 | 80社 | 200社 |
| 利用者数 | 1,500人 | 5,000人 |
| DB容量 | 150GB | 800GB |
| CPU | 8コア | 8コア |
| メモリ | 32GB | 32GB |

サーバー導入後、ハードウェアの性能は変更していない。

#### 2. 処理の集中

1台のDBサーバーで以下の処理を実行している。

- 顧客情報の検索
- 業務データの登録・更新
- 帳票作成
- データ集計・分析

帳票作成時に他の顧客の操作にも影響が出る。

#### 3. データベースの最適化不足

- PostgreSQLを使用
- 過去2年間、本格的なクエリ最適化を実施していない
- インデックスの見直しも行っていない
- 日常的な運用業務により改善時間が不足している

根本原因の詳細な特定はできていない。

### 分析・気づき

- 顧客数やデータ量の増加に対して、
  ハードウェアのリソースが不足している可能性がある。
- 1台のDBサーバーに複数の処理が集中しているため、
  処理負荷を分散できていない可能性がある。
- クエリやインデックスの最適化不足により、
  不必要なリソース消費が発生している可能性がある。
- 今後の顧客数の増加によって、
  現在の性能問題がさらに深刻化する懸念がある。

### 追加確認事項

- PostgreSQLのバージョンと現在の構成
- クエリの実行時間とボトルネック
- データベースの負荷分散の実施状況
- これまでに実施した性能改善策

## Q04 — クラウド移行の可能性と懸念点

### 質問

現在オンプレミスで運用されていますが、
クラウドを利用する選択肢はありますか。

また、クラウド移行を妨げている理由や
懸念点についてお聞かせいただけますか。

### 質問の目的

- クラウド移行に対する経営陣の意向を確認する
- 移行を妨げている要因を特定する
- 技術的・経営的な制約条件を把握する

### クライアントの回答

経営陣はクラウド移行に前向きであり、
AWSとAzureを検討候補としている。

ただし、具体的なサービス調査や
費用試算は実施していない。

#### 1. セキュリティ

- 顧客企業の機密情報・個人情報を扱う
- 一部の顧客との契約で国内データ保管が必須
- 現行環境と同等以上のセキュリティを希望

#### 2. コスト

- クラウド利用料の変動に対する懸念
- 顧客数増加に伴う将来的な費用が不明

#### 3. 移行時の制約・希望条件

| 項目 | 希望条件 |
|---|---|
| 計画停止時間 | 最大2時間 |
| 作業時間帯 | 土日・深夜 |
| データ損失 | 不可 |
| 移行期間 | 6〜12か月以内 |

#### 4. 社内の技術力

| スキル | 経験者数 |
|---|---|
| Linux | 3人 |
| ネットワーク | 2人 |
| PostgreSQL | 2人 |
| AWS基礎 | 1人 |
| Azure基礎 | 0人 |
| 本番クラウド運用 | 0人 |

#### 5. 既存システムとの互換性

- オンプレミスを前提としたアプリケーション
- 移行に必要な改修範囲が不明

#### 6. ベンダーロックイン

- 特定のクラウド事業者への依存
- 将来的な料金上昇への懸念
- 他事業者への移行難易度

#### 経営陣の方針

全面的なクラウド移行に限定せず、
部分移行やオンプレミスの改善も検討する。

### 分析・気づき

- クラウド移行を妨げている要因は、
  技術的な実現可能性だけでなく、
  経営判断に必要な情報の不足にもあると考えられる。
- AWS・Azureの経験者が少なく、
  移行後の運用体制や人材育成も検討する必要がある。
- 顧客情報を扱うため、セキュリティと
  データの国内保管を重視する必要がある。
- 経営陣がクラウド移行に前向きであるため、
  複数のインフラ構成を柔軟に提案できる。

### 追加確認事項

- 現在のITインフラの年間運用費用
- クラウド移行に充てられる予算
- 現在のセキュリティ対策と契約上の要件
- 外部の技術支援や人材教育の利用可否

## Q05 — 現在の運用費用とクラウド移行予算

### 質問

現在のITインフラの運用にかかっている費用と、
クラウド移行に充てられる予算について
お聞かせいただけますか。

### 質問の目的

- 現在のITインフラ費用を把握する
- TCO分析の基準値を取得する
- クラウド移行の予算制約を確認する
- 経営陣のコスト削減目標を把握する

### クライアントの回答

#### 1. 現在の年間運用費用

| 費用項目 | 年間費用 |
|---|---|
| ハードウェア保守費 | 240万円 |
| ソフトウェアライセンス費 | 180万円 |
| 電気・冷却設備費 | 120万円 |
| ネットワーク通信費 | 180万円 |
| サーバー設置スペース費 | 120万円 |
| バックアップ・ストレージ費 | 60万円 |
| 外部技術サポート費 | 150万円 |
| IT担当者3人の人件費 | 2,250万円 |
| 合計 | 3,300万円 |

- 人件費を除いた年間費用：1,050万円
- 人件費を除いた月間費用：87.5万円

#### 2. ハードウェア更新費用

- 5年前の設備購入費：1,200万円
- 今後1〜2年以内に設備更新が必要
- 設備更新の概算費用：1,500万円
- 正式な見積もりは未取得

#### 3. クラウド移行予算

| 項目 | 金額・条件 |
|---|---|
| 初期移行予算 | 1,000万円 |
| 初期移行予算上限 | 1,500万円 |
| 年間総運用費用 | 3,300万円以下が望ましい |
| コスト削減目標 | 15〜20% |
| 投資効果の評価期間 | 5年間 |

初期移行予算に含まれる項目：

- システム改修
- データ移行
- 外部コンサルティング
- 社員教育
- 移行期間中の並行運用

#### 4. 経営陣の方針

- コスト削減は絶対条件ではない
- サービス品質と拡張性の改善も重視する
- IT担当者の人員削減は予定していない
- 運用負担を減らし、システム改善に注力したい

### 分析・気づき

- クラウド移行によってハードウェア保守費、
  電気・冷却設備費、設置スペース費などを
  削減できる可能性がある。
- 人件費が年間運用費用の約68%を占めている。
  人員削減を予定していないため、
  大幅なコスト削減には課題がある。
- 年間600万円の削減を目指す場合、
  人件費以外の費用を約57%削減する必要がある。
  実現可能性は今後の費用試算によって検証する。
- オンプレミスを継続する場合も、
  約1,500万円の設備更新費用が発生する見込みである。
- コストだけでなくサービス品質や拡張性を
  重視しているため、クラウドの特性と
  経営目標が合致する可能性がある。

### 追加確認事項

- 15〜20%のコスト削減目標の算定基準
  （年間運用費用または5年間のTCO）
- 現在の費用のうち、クラウド移行後も残る費用
- 将来的な人員増加の予定
- 設備更新費用1,500万円の詳細な内訳
- AWS・Azureの利用料金と初期移行費用の試算
