## 2. プロジェクトの目的

現行ITインフラの課題を解決し、サービス品質の向上、事業成長への対応、運用効率の改善および中長期的な費用最適化を実現する。

クラウド移行そのものを目的とせず、オンプレミス継続・改善、AWS、Azure、部分的なクラウド移行を比較し、最適な解決策を提案する。

## 8. 受入基準（Acceptance Criteria）

| 評価対象 | 評価方法 |
|---|---|
| 既存機能 | 機能テスト・ユーザー受入テスト |
| 性能 | 性能テスト |
| 拡張性 | 同時接続1,000人を想定した負荷テスト |
| 障害復旧 | 障害復旧テスト・DRテスト |
| セキュリティ | 設定レビュー・脆弱性診断 |
| データ整合性 | 移行前後のデータ比較 |
| 移行費用 | 予算と実績の比較 |
| 運用体制 | 自社担当者による運用実施 |
| 長期的な費用対効果 | TCO予測値と実績値の比較 |

移行前に評価可能なMust要件が未達の場合は、原則として本番移行を承認しない。

移行後に評価するMust要件については、事前に達成可能性を検証し、未達の場合は改善計画を策定する。

Should要件については、他の改善効果や費用対効果とのバランスを考慮して判断する。
