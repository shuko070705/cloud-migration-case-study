# クラウドコンピューティング基礎知識

## 1. オンプレミスとクラウド

### オンプレミス（On-Premises）

企業が自社でサーバーやネットワーク設備を保有し、管理・運用する形態。

### クラウドコンピューティング（Cloud Computing）

外部のクラウド事業者が提供するコンピューティングリソースを、ネットワーク経由で必要に応じて利用する形態。

| 比較項目         | オンプレミス         | クラウド                 |
| ---------------- | -------------------- | ------------------------ |
| 初期投資         | 大きくなりやすい     | 小さく始めやすい         |
| 支払い           | 設備購入・維持費     | 利用量や契約に応じた料金 |
| ハードウェア管理 | 自社                 | クラウド事業者           |
| 拡張性           | 設備の追加購入が必要 | 柔軟に変更可能           |
| 管理の自由度     | 高い                 | サービスによって異なる   |
| セキュリティ     | 主に自社で管理       | 責任を分担               |

### ビジネスへの影響

クラウドは初期投資を抑え、柔軟なリソース調整を可能にする。ただし、長期的なコスト削減が保証されるわけではない。

## 2. 仮想化（Virtualization）

1台の物理サーバー上で複数の仮想マシン（VM）を動作させる技術。

ハイパーバイザー（Hypervisor）がCPU、メモリ、ストレージなどの物理リソースを各仮想マシンに割り当てる。

代表的なクラウドサービス：

- Amazon EC2
- Azure Virtual Machines

### ビジネスへの影響

物理リソースの効率的な利用や、システム環境の柔軟な構築が可能になる。

## 3. クラウドサービスモデル

| モデル | 内容                                 | 代表例            |
| ------ | ------------------------------------ | ----------------- |
| IaaS   | ITインフラを提供する                 | Amazon EC2        |
| PaaS   | アプリケーションの実行環境を提供する | Azure App Service |
| SaaS   | 完成したソフトウェアを提供する       | Microsoft 365     |

サービスモデルによって、利用企業とクラウド事業者の管理範囲が異なる。

### ビジネスへの影響

管理を事業者に任せる範囲が広がることで、企業の運用負担を軽減できる。一方で、システムの自由度や制御範囲が制限される場合がある。

## 4. 拡張性と弾力性（Scalability & Elasticity）

### Scalability

システムが増加する処理負荷に対応できる能力。

### Vertical Scaling（Scale Up）

既存サーバーのCPUやメモリなどの性能を向上させる方法。

### Horizontal Scaling（Scale Out）

サーバーの台数を増やして処理負荷を分散する方法。

### Elasticity

需要に応じてコンピューティングリソースを動的に増減させる能力。

### ビジネスへの影響

将来的な事業拡大に対応しながら、過剰な設備投資を抑えられる可能性がある。

## 5. 可用性と信頼性（Availability & Reliability）

| 用語              | 意味                                   |
| ----------------- | -------------------------------------- |
| Availability      | システムが利用可能である度合い         |
| High Availability | システムの停止時間を最小限に抑える設計 |
| Redundancy        | 予備・重複したリソースを用意すること   |
| Fault Tolerance   | 障害発生時も処理を継続できる能力       |
| Disaster Recovery | 大規模障害からシステムを復旧する仕組み |

### ビジネスへの影響

サービス停止は売上、顧客満足度、企業の信頼性に影響を与える。そのため、コストだけでなくサービスの継続性も考慮する必要がある。

## 6. 財務関連の基礎知識

### CapEx（Capital Expenditure）

資本的支出。サーバーや設備など、長期間使用する資産への投資。

### OpEx（Operating Expenditure）

運用支出。クラウド利用料、保守費用、人件費など、継続的な運用に必要な費用。

### TCO（Total Cost of Ownership）

総保有コスト。一定期間におけるシステムの導入、運用、保守、更新、廃棄などに必要な総費用。

TCO = 初期費用 + 運用費用 + その他のライフサイクル費用

### 主な費用項目

- ハードウェア購入費
- クラウドサービス利用料
- ソフトウェアライセンス費
- 電気・冷却設備費
- ネットワーク通信費
- IT管理人件費
- バックアップ費用
- システム移行費用

### ビジネスへの影響

初期費用や月額利用料だけではなく、長期的な総費用に基づいてインフラ構成を評価する必要がある。

## 7. 責任共有モデル（Shared Responsibility Model）

クラウド環境では、クラウド事業者と利用企業がセキュリティに関する責任を分担する。

クラウド事業者は基盤となるインフラを管理する。一方、利用企業にはデータ保護、アクセス管理、サービス設定などの責任が残る。

具体的な責任範囲は利用するサービスによって異なる。

## 8. 本プロジェクトとの関連性

Nexus Solutions Inc.は3年以内に法人顧客数を2倍にすることを目指している。

そのため、以下の観点を重視してインフラ構成を評価する。

- 拡張性
- 長期的なコスト効率
- サービスの可用性
- セキュリティ
- IT管理担当者の運用負担

具体的なインフラ構成を推奨するには、クライアントへの追加ヒアリングと現状分析が必要である。
